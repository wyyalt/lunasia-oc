# 星璃写真

## 默认与优先级

用户当前要求优先。用户只说“星璃”或调用本 skill 时，先提供场景主题选项，不立即调用生图工具。经典星光写真默认 9:16 近景半身、正面或轻微三分之四构图；其他主题按主题建议选择构图，不强制套用半身竖版。

读取 `references/identity-style.md`、`references/variations.json` 和 `state/recent.json`。两个 `assets/reference-*.jpg` 是人物和画风基准，始终作为实际图片输入；不要用已生成的图片替换基准，避免逐代漂移。可额外传入用户明确指定的编辑目标或构图参考，并分别标注用途。

“开心”“治愈”“清冷”等只覆盖情绪及相关姿态，不隐含换场景、色温或画风。天宫、横版、全身等按明确要求启用；一次特殊场景不修改常规默认。明确“继续上一张/再来一张同场景”则沿用该场景。

## 交互流程：选主题 → 选情绪 → 推荐景别与动作 → 审阅提示词 → 确认生成

### 1. 选择写真类型

“类型”指场景与叙事主题，不是情绪。用户未指定主题时，读取 `references/portrait-types.md`，展示其中十三个编号选项，每项一句简短场景说明，并允许自定义、组合或随机。请用户回复编号或名称，然后等待选择；此阶段不生成图片。

如果用户已明确主题（例如“云阙天宫”“风雪归人”）或提供详细场景要求，跳过主题选择，进入情绪选择。只指定“开心”“治愈”等情绪时保留该情绪，仍展示主题菜单，主题选好后不再重复询问情绪；明确说常规写真则采用经典星光写真。主题与情绪都明确时直接展示提示词。

### 2. 选择情绪

主题选好而情绪未指定时，读取 `references/emotions.md`，展示带字母编号的情绪选项，等待用户选择。可按主题推荐一两项，但不替用户决定。场景使用数字编号、情绪使用字母编号，避免短回复含义混淆；依当前等待阶段解读回答，保留已选主题。

允许自定义、混合情绪或“你来搭配”。若用户在某一选择阶段说“随机”，只代选该阶段，不默认为所有后续选择随机；明确说“全部随机/都由你搭配”才同时代选所有未指定项。随机或选择情绪均不等于确认生图。每次新的普通请求都要展示本次提示词。

### 3. 推荐景别并构建完整提示词

主题与情绪确定后，读取 `references/framing.md`，结合场景规模、情绪是否依赖面部细节、动作是否需要展示全身和用户最近的景别记录，推荐本次景别。景别必须有变化，不要默认每次近景半身：经典星光写真也可在特写、近景半身和中景之间切换；宏大场景优先中景、全身或环境远景；需要表现细微情绪时优先特写或近景。推荐后说明一句理由，用户未指定时按推荐执行，用户指定时优先。

根据 `references/variations.json` 和最近记录，为本次主题与情绪推荐一个具体动作；动作可以由用户直接指定或覆盖。景别与动作的推荐要说明理由，例如“选择中景是为了同时表现神秘眼神和壁画互动”。景别、动作与场景、情绪一起写入完整提示词。提示词包含主题、情绪、推荐景别及理由、比例、参考图用途、人物与画风、具体表情、动作、身体朝向、背景与光线，以及必要排除项。说明会实际传入两张原始参考图。不要只提供概要或情绪标签。

完整提示词按 `references/prompt-template.md` 的字段顺序组织。展示后，将本次待确认方案和完整提示词写入 `state/pending.json`；写入失败时仍展示提示词，但在确认生成前必须重新核对当前对话中的最近版本。

在提示词之后询问：“按这份提示词生成吗？也可以直接告诉我想修改的地方。”等待用户明确确认（如“确认”“生成”“就这样”），在此之前不调用任何生图工具。类型选择本身不是生成确认。

用户要求修改时更新并重新展示完整提示词，等待确认。若用户明确说“改成……并直接生成”，该消息已授权对应改动和生成，不再重复确认。用户明确要求本次跳过确认时遵从，但不据此永久改变默认流程。

### 4. 按已确认提示词生成

确认仅对应当前对话中最近展示的那份提示词，不复用其他会话或旧版本的确认。优先读取并校验 `state/pending.json` 的 pending_id、提示词版本和参考图路径；若与当前展示版本不一致，以当前对话最近版本为准并重新写入。将确认的完整提示词直接交给工具，附上原始参考图；不在确认后重新随机主题、情绪、景别、动作、朝向或暗中添加场景、道具。仅允许不改变语义的接口适配。生成结束后不再读取、校验或清空 pending；遗留 pending 不代表有效授权，下次请求只以当前对话最近展示并确认的版本为准。

不在生成后写入近期记录。避重仅在生成前参考已有记录和当前对话，不补写历史。不为本流程建立额外长期偏好或全局 memory。

## 具体方案与避重

1. 按用户已选情绪设计具体表情，从变化库借鉴景别、手部动作和朝向；变化库仅作示例，不限制新情绪或兼容动作。景别推荐必须同时考虑场景规模、表情可读性、动作信息量和最近生成记录；动作推荐也必须考虑场景、情绪、景别和抓拍感。已指定的维度不随机。经典写真朝向倾向：正面 50%，轻微左转 20%，轻微右转 20%，明显侧面/回眸合计 10%。主题远景按叙事选择行走、停步、提裙等自然动作，可望向远方，不硬套近景手势和朝向比例。
2. 查看最近记录和当前对话，尽量避免最近三次的动作；避免紧邻重复情绪及连续明显侧身。用户明确重复的要求优先。记录缺失时从当前对话获取近期组合，不能编造历史。
3. 检查组合是否自然：害羞可侧眸拢发，开心可挥手；动作不遮挡主要面部。无需每张加入蝴蝶或道具。不要在生成提示词里仅写“随机选择”，必须先把选择落实为一组具体指令。
4. 所有主题都必须加入“电影抓拍感”条件：动作发生在一个自然瞬间，身体重心、视线、手指、发丝和衣料动态彼此连贯，像被镜头偶然捕捉。人物不要正对镜头摆标准姿势，不要僵硬对称、刻意摆手、刻意挺胸、刻意抬下巴或像证件照一样站定。情绪仍需清晰可读，但通过当下反应和微动作表现。
5. 将确定的方案和抓拍要求写进本次完整提示词，按上述流程等待确认。

## 工具与参考图

先检查专用 `generate_starli_reference_image` 工具是否可调用，并查看其真实参数和参考图能力。仅在它能满足所选方案、使用正确基准图且符合当前用户授权时优先使用；不虚构参数，不为调用它改写服务器配置或另建付费 API 路径。

工具缺失或能力不足时使用可用的内置 `image_gen`，实际附上本 skill 的两张原始参考图。遵循当前 imagegen 技能及工具接口；本地图片需要预览时先预览。若仅能发送文字，不称其为参考图生成；说明缺少能力。内置工具不可用时不擅自切换收费 CLI/API。

提示词顺序：输出尺寸与构图 → 两张图的人物/画风参考角色 → 身份与画风要点 → 具体表情/动作/朝向 → 当前场景 → 必要排除项。用户已有详细提示词时保留其意图，避免额外添加场景或饰物。

## 生成后立即交付并结束

生图工具返回成功后，直接交付图片并结束本轮，不再调用任何其他工具或执行额外操作。工具已经展示图片时，不重复渲染，只需一句简短完成说明。

禁止生成后的全部收尾操作：不读取、校验、清空或写入 `state/pending.json`；不读取或更新 `state/recent.json`；不记录日志、写 memory、检查文件、复制图片、检查尺寸、重新打开或放大成图；不检查人物、画风、表情、手部或构图；不生成检查报告、不自动修正或重试。不要将这些操作移到所谓后台或交付前的轻量收尾中。

交付只使用生图工具已经返回的图片和路径，不声称已经验证画面细节或原生分辨率。本规则优先于通用 imagegen 技能的生成后检查、保存和迭代流程。只有用户明确另行要求检查、修改、保存到指定位置等操作时，才执行对应工作。
